┌──────────────────────────────────────────────────────────────────────────────┐
│                          COMPLIANCE CHECKLIST                                │
└──────────────────────────────────────────────────────────────────────────────┘

    For every new file:
    ☐ Uses .echo. prefix in filename
    ☐ Appropriate extension chosen (.scm, .glisp, .lisp, .lsp, .ls, .s)
    ☐ File header with documentation block
    ☐ Functions documented with purpose, args, returns, examples
    ☐ Follows naming conventions (kebab-case, ?, !, ->)
    ☐ Code follows style guide (2 space indent, 80-100 char lines)
    ☐ Tests created (if applicable)
    ☐ No secrets or sensitive data hardcoded

    touch my-module.echo.scm
    
    # Create EchoLisp-specific file
    touch web-api.echo.glisp

    (load "examples/calculator.echo.scm")
    
    # Find all echo files
    find . -name "*.echo.*"


┌──────────────────────────────────────────────────────────────────────────────┐
│                             KEY PRINCIPLES                                   │
└──────────────────────────────────────────────────────────────────────────────┘

    1. CONSISTENCY    → Always use .echo. prefix
    2. CLARITY        → Choose descriptive names
    3. DOCUMENTATION  → Document all public APIs
    4. TESTING        → Test your code
    5. FUNCTIONAL     → Prefer immutability and pure functions
    6. PORTABLE       → Use .echo.scm for standard Scheme
    7. PRAGMATIC      → Use .echo.glisp for EchoLisp features
